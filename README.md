# AI FIGHT

Пиксельный аркадный файтинг, в котором побеждает не сильнейший, а **убедительнейший**.
Два игрока выбирают бойцов и арену, вводят тему спора и свои аргументы. Судья оценивает обе позиции
по пяти критериям, а игра разыгрывает вердикт как настоящий бой: победитель добивает соперника
и встаёт в победную позу, проигравший падает, при ничьей оба остаются на ногах.

```
START GAME → SELECT FIGHTER (P1, P2) → SELECT ARENA → ENTER THE DEBATE
  → JUDGE IS THINKING → BATTLE (3·2·1·FIGHT! → удары → K.O. / DRAW) → RESULTS (REMATCH / NEW GAME)
```

Игра полностью автономна: судья — встроенный тестовый судья на сервере игры.
**Никаких API-ключей, `.env`, внешних ИИ-сервисов и платных подписок не нужно.**
Игрокам ничего не нужно устанавливать — игра открывается по ссылке в любом современном браузере
(Chrome, Safari, Firefox, Edge; компьютер, планшет, смартфон).

## Публикация: GitHub + Render

### Шаг 1. Загрузить проект на GitHub (через браузер)

**Важно:** структура папок должна сохраниться. Если все файлы окажутся в корне репозитория
без папок `client` и `server`, сборка на Render остановится с сообщением
`AI FIGHT: project folders are missing`.

Используйте **Chrome, Edge или Firefox** — Safari не умеет загружать на GitHub папки перетаскиванием.
Кнопка «choose your files» тоже не подходит: она загружает только файлы, без папок.

1. Войдите на https://github.com, нажмите **+** → **New repository**, имя `ai-fight`,
   галочки README / .gitignore / license **не ставьте** → **Create repository**.
2. Нажмите ссылку **uploading an existing file**.
3. Откройте в Finder папку `ai-fight` и выделите внутри неё **папки `client`, `server`, `tests`,
   `tools`, `source-art` и файлы `package.json`, `package-lock.json`, `render.yaml`, `README.md`,
   `Dockerfile`** (Cmd+A). Перетащите выделенное **одним движением** в окно браузера.
4. Дождитесь, пока в списке появятся строки вида `client/src/App.jsx`, `server/index.js`
   (с путями через `/`), и нажмите **Commit changes**.
5. Проверьте корень репозитория: там должны быть **папки** `client`, `server` и файлы
   `package.json`, `render.yaml`. Внутри `client` — `index.html`, `vite.config.js`, `src`, `public`.

> Скрытые файлы (`.gitignore`, `.node-version`) Finder при перетаскивании не берёт — это нормально.

### Шаг 2. Подключить репозиторий к Render

1. Зайдите на https://render.com и войдите через **GitHub** (кнопка «GitHub» на странице входа).
2. Нажмите **New +** → **Web Service**.
3. Выберите **Build and deploy from a Git repository** → **Connect GitHub**, разрешите доступ
   к репозиторию `ai-fight` и нажмите **Connect** напротив него.
4. Заполните настройки:

   | Поле | Значение |
   |---|---|
   | Name | `ai-fight` (станет частью ссылки) |
   | Language / Runtime | **Node** |
   | Branch | `main` |
   | Root Directory | *(пусто)* |
   | Build Command | `npm install && npm run build` |
   | Start Command | `npm start` |
   | Instance Type | **Free** |

   Переменные окружения добавлять **не нужно**. (Необязательно: `NODE_VERSION` = `24`.)
5. Нажмите **Create Web Service** (или **Deploy Web Service**). Сборка идёт 2–4 минуты;
   в логе должно появиться `AI FIGHT server listening on port …`, а статус — **Live**.

*Альтернатива:* **New +** → **Blueprint** → выбрать репозиторий — Render возьмёт все настройки из `render.yaml`.

### Шаг 3. Получить публичную ссылку

Вверху страницы сервиса в Render появится адрес вида **`https://ai-fight-xxxx.onrender.com`**.
Это и есть публичная HTTPS-ссылка на игру — её можно отправлять коллегам.

Особенность бесплатного тарифа Render: если игрой 15 минут никто не пользуется, сервер «засыпает».
Первое открытие после паузы занимает 30–60 секунд, дальше всё работает быстро.
Каждое изменение в репозитории на GitHub Render автоматически пересобирает и публикует.

## Локальный запуск (для разработчиков, необязательно)

Нужен Node.js 20.19+ (рекомендуется 24 LTS).

```bash
npm install
npm run build
npm start          # http://localhost:8787
```

Режим разработки с горячей перезагрузкой: `npm run dev` → http://localhost:5173. Тесты: `npm test`.

## Переменные окружения (все необязательные)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8787` | Порт сервера (Render задаёт сам). |
| `RATE_LIMIT_PER_MIN` | `30` | Сколько боёв в минуту можно запустить с одного IP. |

## Как судит судья

Судья — `server/mockJudge.js`, выполняется на сервере (`POST /api/judge`), без интернета и внешних сервисов.
Его правила и инструкция — в `server/judgeKnowledge.js`. Это логический арбитр, а не счётчик слов:

1. Разбивает каждую позицию на фразы и различает **подтверждённые факты** (цифры, проценты, отчёт, данные
   системы), **утверждения** (сказано, но не подтверждено), **ссылки на правила**, **предположения**,
   **эмоциональные доводы** (просьбы, «пожалуйста») и **попытки повлиять** (подарки, обещания, угрозы).
2. Если спор про **циклы**, применяет рабочие правила:
   * циклы — показатель отклонения монтажника от нормативов эффективности;
   * не выполнен план на 100% или не закрыт дневной график → +1 цикл;
   * снять цикл можно только при положительной динамике по эффективности на следующий рабочий день;
   * без положительной динамики цикл сохраняется; автоматически и со временем циклы не списываются.

   Судья выясняет, что факты в споре реально устанавливают (динамика подтверждена данными, только заявлена,
   оспорена или неизвестна), и какой исход требуют правила. Доказать улучшение должен тот, кто просит снять
   цикл. Утверждения игроков не считаются доказанными фактами.
3. Переводит анализ в пять критериев (логика 25%, убедительность 25%, обоснованность 25%, по теме 15%,
   контраргументы 10%). Правила и данные весят больше, чем просьбы и обещания; подкуп, давление,
   оскорбления и «сам спишется» снижают баллы.
4. **Ничья — только при действительно равных позициях.** Разница даже в 1 балл — победа. При равенстве баллов
   судья сравнивает суть (соответствие правилам, данные, манипуляции, ссылки на нормативы, обоснования);
   победитель получает решающий балл, поэтому табло, текст вердикта и анимация боя всегда совпадают.

Пример «Заполнить пример»: Айжамал не снимает цикл из-за отклонения и отсутствия динамики, Айылчы предлагает
шоколадку → победа Айжамал: её позиция соответствует правилам, а обещание шоколадки к нормативам отношения
не имеет. Судья при этом отмечает, что утверждение Айжамал об отсутствии динамики не подтверждено данными.

Для споров на другие темы применяется общий анализ: обоснования, конкретика и данные, работа с позицией
оппонента, структура; манипуляции и эмоции снижают оценку.

На экране результатов есть панель **«Анализ фактов»**: каждая фраза игроков с пометкой, к какому типу
она отнесена, и список учтённых правил.

Ответ `/api/judge` (поля, которые использует игра):

```json
{
  "winner": "player1",
  "player1_score": 62, "player2_score": 7,
  "player1_criteria": { "logic": 81, "persuasiveness": 60, "evidence": 40, "relevance": 90, "rebuttal": 35 },
  "player2_criteria": { "logic": 5, "persuasiveness": 5, "evidence": 5, "relevance": 7, "rebuttal": 20 },
  "player1_strengths": ["…"], "player1_weaknesses": ["…"],
  "player2_strengths": [], "player2_weaknesses": ["Попытка подкупа: «я завтра шоколадку занесу»."],
  "reasoning": "Победитель — Айжамал! По правилам цикл можно снять только…",
  "final_verdict": "Победитель — Айжамал! Позиция соответствует правилам работы с циклами.",
  "confidence": "medium",
  "analysis": {
    "context": "cycles",
    "fact_status": "no_improvement_claimed",
    "rule_outcome": "keep",
    "facts": [{ "side": "player2", "type": "influence", "label": "Попытка повлиять", "text": "я завтра шоколадку занесу" }]
  }
}
```

Ввод проверяется и в браузере, и на сервере: тема 5–200 символов, имя до 20 символов,
аргумент от 40 символов и 6 слов до 2000 символов.

## Структура проекта

```
ai-fight/
├─ client/                       фронтенд (Vite + React + Phaser 3)
│  ├─ index.html
│  ├─ vite.config.js             конфигурация сборки фронтенда
│  ├─ public/assets/
│  │  ├─ fighters/*.png          8 бойцов (прозрачный фон)
│  │  └─ arenas/*.jpg            3 арены + превью *_thumb.jpg
│  └─ src/
│     ├─ main.jsx, App.jsx       точка входа и переключение экранов
│     ├─ styles.css
│     ├─ screens/                MainMenu, CharacterSelect, ArenaSelect, MatchForm, Judging, Battle, Results
│     ├─ components/             Button, MuteButton
│     ├─ game/BattleScene.js     сцена боя (Phaser)
│     ├─ game/script.js          превращает вердикт в хореографию боя
│     ├─ audio.js                8-битные звуки и музыка (синтез в браузере, без файлов)
│     ├─ data.js                 бойцы и арены
│     └─ api.js                  запрос к судье на сервере
├─ server/
│  ├─ index.js                   Express: отдаёт dist/ и API /api/judge, /api/health
│  ├─ mockJudge.js               судья: анализ фактов, правил и манипуляций
│  ├─ judgeKnowledge.js          правила о циклах и инструкция судьи
│  ├─ rules.js                   лимиты ввода, критерии и веса, расчёт итога и ничьей (их же использует фронтенд)
│  └─ check-structure.js         проверка папок перед сборкой
├─ tests/rules.test.js           юнит-тесты (npm test)
├─ source-art/                   исходные изображения
├─ tools/prepare_assets.py       подготовка графики из source-art/
├─ package.json
├─ package-lock.json
├─ render.yaml                   конфигурация Render
├─ Dockerfile
└─ README.md
```

`npm run build` сначала проверяет структуру папок, затем собирает фронтенд из `client/` в `dist/`
(в корне проекта). `npm start` запускает Express, который отдаёт `dist/` и обрабатывает `/api/*`.
Фронтенд обращается к серверу по относительному адресу `/api/judge`, поэтому привязки к `localhost` нет.

## Управление

Мышь / тач везде. На выборе бойцов — стрелки и Enter. В бою — кнопка **▶▶ FAST** ускоряет показ.
Кнопка звука в углу выключает музыку, эффекты и голос (настройка запоминается).
На телефоне бой удобнее смотреть горизонтально.
